AI Firewall

An out-of-band LLM prompt inspection service. External applications call this API before sending prompts to their own models — getting a structured pass / monitor / block verdict in milliseconds.

Your App
→
POST /v1/inspect
→
firewall-api
→
pass monitor block
+ violations[], X-Firewall-Latency-Ms, MITRE ATLAS tags
⚡
Latency-first design
Heuristics run in microseconds. Parallel cache + vector layers short-circuit before the LLM is ever called. Cached verdicts return in <10 ms.
🔑
API key → Policy binding
Every key is bound to one or more named policies. Different apps get different detection rules with zero code changes.
🗺️
MITRE ATLAS mapped
Every violation is tagged with an ATLAS technique ID (AML.T0051 Prompt Injection, AML.T0054 Jailbreak, etc.) — ready for SOC reporting.
🏗️
Three-app monorepo
firewall-api handles inspection at the edge. policy-manager provides admin dashboard + REST API. firewall-tester runs prompt sets and serves a reporting UI.

Detection Pipeline

Layers are ordered by cost. Each layer can short-circuit and return immediately, skipping all subsequent (more expensive) layers.

0
Heuristics
Compiled regex rules — injection keywords, jailbreak phrases, PII patterns (SSN, credit card, API secrets), obfuscation (base64/hex/unicode). Zero I/O. Runs all categories except Content Moderation.
~0 ms
short-circuits
1
Verdict Cache
SHA-256 of normalized prompt + profile ID. Checks colocated Cache API first, falls back to Workers KV. Fires in parallel with Layer 2.
~5–10 ms
short-circuits
2
Vector Similarity
Embeds the prompt with bge-small-en-v1.5, queries the Vectorize index of known attack signatures. Only runs for Prompt Injection and Jailbreak detections. Skipped entirely if neither is active.
~20–40 ms
short-circuits
3
LLM Classification
Calls llama-3.3-70b-instruct-fp8-fast for content-safety classification. Only runs for Content Moderation detections. Skipped entirely if Content Moderation is not active in the profile.
~1–3 s
content-mod only

Layers 1 and 2 fire in parallel. A cache hit short-circuits before awaiting the L2 vector result. L3 only runs when Content Moderation detections are enabled — most requests never call the LLM.

How It Works — Full Request Flow

Every call to POST /v1/inspect passes through up to six stages. The firewall bails out at the earliest confident decision, so most requests never reach the AI models.

1
Authentication & Policy Resolution

The X-API-Key header is SHA-256 hashed. Two KV reads resolve the full SecurityProfile:

  1. POLICY_CACHE KV — hash → profileId pointer
  2. POLICY_CACHE KV — profileId → full SecurityProfile document

The resolved SecurityProfile travels through the rest of the pipeline as a plain object. firewall-api never calls policy-manager at runtime — all profile data is pre-replicated into KV by policy-manager on every write. KV propagates globally in ~60 s.

→ 401 on missing / invalid / revoked key
2
Layer 0 — Heuristics (~0 ms · no I/O)

Compiled RegExp rules run synchronously against the raw prompt. Rules map to Detection Settings in the SecurityProfile. Rules are grouped by category:

  • Prompt Injection — "ignore all previous instructions", instruction override patterns, system-token injection (<|system|>, ###SYSTEM###), mode-switch phrases.
  • Jailbreak — explicit "jailbreak" keyword, DAN pattern, developer-mode activation, roleplay/persona overrides, persistence phrases ("from now on you will…").
  • Sensitive Data — API keys (keyword + value, or vendor-prefix patterns: sk-, ghp_, AKIA…), SSN, credit card, email, phone — with context-awareness (bare PII without surrounding keywords does not trigger).
  • Obfuscation — base64 blobs, hex blobs, unicode zero-width characters, delimiter stacking.

Content Moderation has no L0 rules — it is handled entirely by Layer 3.

Short-circuit logic: if any violation has mode: block, the pipeline returns immediately. "Ignore all previous instructions" is a block-mode detection and exits in 0 ms.

short-circuits → block if any violation.mode === "block"
continues → layers 1+2 if no block
3
Layer 1 — Verdict Cache (~5–10 ms)

The prompt is lowercased, whitespace-collapsed, then SHA-256 hashed. The cache key is hash:profileId. Two stores are checked in order:

  1. Workers Cache API — colocated with the Worker instance. Sub-millisecond. Uses a synthetic URL https://firewall-cache.internal/<key>.
  2. VERDICT_CACHE KV — global fallback for cross-region cache warming. ~5–10 ms.

Layer 1 fires in parallel with Layer 2 (vector). A cache hit short-circuits: the stored verdict is returned immediately.

On a verdict write, the result is saved to both stores with TTL = profile.cacheTtlSeconds (default 3600 s). Cache writes happen via ctx.waitUntil() so they never add latency to the response.

To force a fresh inspection without waiting for TTL expiry, send X-Bypass-Cache: 1.

short-circuits → returns cached verdict
continues → L2 result + L3 (if content-mod) on miss
4
Layer 2 — Vector Similarity (~20–40 ms · requires Vectorize · injection + jailbreak only)

Only runs if Prompt Injection or Jailbreak detections are active in the profile. Skipped entirely if neither is configured. Runs concurrently with Layer 1 (cache).

The prompt is embedded using @cf/baai/bge-small-en-v1.5 (384-dimensional dense vector). The vector is queried against the Vectorize index (ai-firewall-attacks, cosine metric, top-5 results).

If the top match exceeds the similarity threshold (default 0.85), a violation is created inheriting the ATLAS tag from the matched signature's metadata.

The Vectorize index is seeded via scripts/seed.ts with known attack prompts and extended through the policy-manager's POST /api/signatures endpoint — each new signature is embedded and upserted on write.

short-circuits → block if any L2 violation is block-mode
continues → L3 (content-mod only) if no block
5
Layer 3 — LLM Safety Classification (~1–3 s · Content Moderation only)

Only runs when Content Moderation detections are active in the profile. Skipped entirely for profiles that do not include a Content Moderation policy. Calls @cf/meta/llama-3.3-70b-instruct-fp8-fast via Workers AI with a structured classification prompt containing content safety categories including:

  • Violence, hate speech, CSAM, weapons, self-harm
  • Election interference, financial crime, privacy violation
  • Code interpreter abuse / data exfiltration

The LLM is explicitly instructed not to flag API keys, credentials, or PII as content-safety violations — those are handled by L0 heuristics.

Detected categories are mapped to ATLAS techniques and added as Violations. The violation mode (block/monitor) is inherited from the Content Moderation detection configuration in the profile.

If the call throws (model timeout, upstream error), behavior is controlled by profile.failOpen: true passes through with a log warning; false forces a block.

violations added → verdict determined by mode
6
Verdict

There is no numeric score. Verdict is determined by the worst violation mode across all layers:

pass
HTTP 200
No violations found
monitor
HTTP 200
Violations found, all mode: monitor
block
HTTP 403
Any violation has mode: block

Each Detection in the SecurityProfile has a mode: "block" | "monitor" field set by the admin. One detection configured as block is enough to produce a block verdict regardless of other violations.

The verdict, all violations (with ATLAS tags), and the profile name are returned in the response body. Latency is returned in response headers — not in the body. The result is written to cache via ctx.waitUntil() so subsequent identical prompts are answered from the verdict cache in <10 ms.

What happened, step by step
  1. Request arrived at the Cloudflare edge closest to the caller.
  2. Auth middleware SHA-256 hashed the key → two KV reads → loaded the default-strict SecurityProfile.
  3. Layer 0 ran regex rules synchronously. The set-inj-override rule — /ignore\s+(?:(?:all|any|…)\s+)*instructions?/i — matched. The Instruction Override detection has mode: block → pipeline short-circuits immediately.

Storage Design

Store What lives here Who reads it Why
R2 Profile documents, audit logs, signature metadata policy-manager only Durable, cheap-at-rest. Tolerates eventual consistency.
KV Denormalized SecurityProfiles; hashed API key→profileId; verdict cache firewall-api (hot path) Globally distributed, sub-millisecond reads. firewall-api never touches R2 per-request.
D1 users, sessions, events, inspect_keys tables firewall-tester + policy-manager (shared) Session auth for both apps. Test run history. Admin-registered Inspect-tab profile registry.
Vectorize Embeddings of known attack signatures firewall-api (Layer 2, injection/jailbreak only) Native cosine similarity search at the edge.

On every policy write the policy-manager pushes the updated document to both R2 (source of truth) and KV (fast read replica). KV propagates globally in ~60 s.

Code Walkthrough — firewall-api/index.ts

This is the Worker's entry point. Cloudflare calls app.fetch(request, env, ctx) on every incoming HTTP request. Everything starts here.

typescript · apps/firewall-api/src/index.ts
// ── 1–6  Imports ─────────────────────────────────────────────────────
import { Hono } from 'hono';
import { InspectRequestSchema, MAX_PROMPT_BYTES } from '@firewall/shared';
import type { SecurityProfile } from '@firewall/shared';
import type { Env } from './env.js';
import { authMiddleware } from './middleware/auth.js';
import { runPipeline } from './pipeline.js';

// ── 8  Create the Hono app ────────────────────────────────────────────
const app = new Hono<{ Bindings: Env }>();

// ── 10–13  Global error handler ───────────────────────────────────────
app.onError((err, c) => {
  console.error('[firewall-api] unhandled error:', err);
  return c.json({ error: 'Internal server error', code: 'INTERNAL_ERROR' }, 500);
});

// ── 15–16  Utility routes ─────────────────────────────────────────────
app.get('/',       c => c.text('AI Firewall API v2'));
app.get('/health', c => c.json({ status: 'ok', version: 2 }));

// ── 18  Register the main route with auth middleware ──────────────────
app.post('/v1/inspect', authMiddleware, async c => {
  const body = await c.req.json();

  // ── 21–27  Reject oversized prompts early ──────────────────────────
  const byteLen = new TextEncoder().encode(body?.prompt ?? '').length;
  if (byteLen > MAX_PROMPT_BYTES) {
    return c.json(
      { error: `Prompt exceeds ${MAX_PROMPT_BYTES} bytes`, code: 'PROMPT_TOO_LARGE' },
      413,
    );
  }

  // ── 29–32  Validate request shape with Zod ─────────────────────────
  const parsed = InspectRequestSchema.safeParse(body);
  if (!parsed.success) {
    return c.json({ error: 'Validation error', code: 'VALIDATION_ERROR', details: parsed.error.flatten() }, 400);
  }

  // ── 34–36  Read data set by auth middleware ────────────────────────
  const profile    = c.get('profile' as never) as SecurityProfile;
  const requestId  = crypto.randomUUID();
  const bypassCache = c.req.header('X-Bypass-Cache') === '1';

  // ── 38–54  Run pipeline and emit latency as headers ────────────────
  const wallStart = Date.now();
  const result = await runPipeline(parsed.data, profile, c.env, c.executionCtx, requestId, bypassCache);
  const wallMs = Date.now() - wallStart;

  c.header('X-Firewall-Request-Id', requestId);
  c.header('X-Firewall-Cached', result.cached ? 'true' : 'false');
  if (result.cached) {
    c.header('X-Firewall-Latency-Ms', String(wallMs));
  } else if (result.latencyMs) {
    c.header('X-Firewall-Latency-Ms', String(result.latencyMs.total));
    for (const [layer, ms] of Object.entries(result.latencyMs.perLayer)) {
      c.header(`X-Firewall-${layer}-Ms`, String(ms));
    }
  }
  const { latencyMs: _dropped, ...responseBody } = result;
  const status = result.verdict === 'block' ? 403 : 200;
  return c.json(responseBody, status);
});

// ── 43  Export — Cloudflare calls app.fetch() on every request ────────
export default app;
LinesWhat it does and why
1 Import Hono. The web framework. Provides routing (app.post), middleware chaining, and request/response helpers (c.req.json(), c.json()). Without it you'd write a giant if/else on request.url and manually build every new Response().
2 Import InspectRequestSchema and MAX_PROMPT_BYTES from the shared package. InspectRequestSchema is a Zod schema that validates the request body has the right shape. MAX_PROMPT_BYTES is 32 * 1024 — the hard cap on prompt size.
3 import type — TypeScript only, erased at runtime. SecurityProfile is used to type the value retrieved from middleware context on line 34. This import produces zero JavaScript output.
4 Import Env — the interface that describes every Cloudflare binding available to this Worker: AI, POLICY_CACHE, VERDICT_CACHE, FIREWALL_VECTORIZE. Typed so c.env.POLICY_CACHE is known to be a KVNamespace at compile time.
5 Import authMiddleware. This function runs before the route handler on every POST /v1/inspect. It hashes the X-API-Key, does two KV reads to resolve the SecurityProfile, and calls c.set('profile', profile) so the handler can read it on line 34. If auth fails it returns 401 and the handler never runs.
6 Import runPipeline. The 4-layer detection engine (Layer 0 heuristics → Layer 1 cache → Layer 2 vector → Layer 3 LLM). Called on line 38 after auth and validation pass.
8 Create the Hono app. new Hono<{ Bindings: Env }>() — the generic parameter tells Hono the shape of c.env so bindings are type-safe inside every route handler. This is just a router object at this point; it becomes a real Worker when exported on line 43.
10–13 Global error handler. app.onError catches any unhandled exception thrown inside any route or middleware. Without this, a runtime error returns an empty 500 with no body — hard to debug. This ensures every error at least logs to Workers Logs and returns a structured JSON response.
15–16 Utility routes. GET / returns plain text — useful as a smoke test. GET /health returns {"status":"ok"} — used by uptime monitors. Neither requires auth because no policy data is involved.
18 Register the main route with middleware chaining. Hono runs arguments left to right: authMiddleware first, then the async c => {...} handler. If authMiddleware returns a response (401) the handler is never called. This is the same pattern as Express middleware — each function either calls next() to continue or returns a response to short-circuit.
19 Parse the JSON body. c.req.json() reads and deserialises the request body. We do this before Zod so we can check the byte length on the next line without Zod's overhead.
21–27 Reject oversized prompts before any validation or AI call. TextEncoder measures the UTF-8 byte length (not character count — a single emoji is 4 bytes). Prompts over 32 KB return 413 Payload Too Large immediately. This prevents a malicious caller from sending a 10 MB payload that would slow down the pipeline.
29–32 Zod schema validation. safeParse returns { success: false, error } instead of throwing — so we handle bad input gracefully with a 400 and a structured error. parsed.error.flatten() formats the Zod errors into a readable object. If this passes, parsed.data is typed as InspectRequest for the rest of the handler.
34 Read the SecurityProfile from middleware context. c.get('profile') retrieves the value that authMiddleware stored with c.set('profile', profile). This is Hono's typed context — a type-safe way to pass data between middleware and handlers within the same request.
35 Generate a request ID. crypto.randomUUID() is available in the Workers runtime without any import. The ID is returned in the response body and appears in every log line — makes it trivial to trace a specific request through Workers Logs.
36 Bypass cache flag. If the caller sends X-Bypass-Cache: 1, the Layer 1 verdict cache is skipped — the pipeline always runs all layers. Useful during development when you want to test a prompt without getting back a stale cached verdict.
38 Run the 4-layer pipeline. Passes the validated request, resolved profile, Worker env (KV / AI / Vectorize bindings), c.executionCtx (for ctx.waitUntil — writes verdict cache after response is sent), request ID, and bypass flag.
38–54 Emit latency as response headers, not body. Cache hits get only X-Firewall-Latency-Ms (the actual cache-lookup cost). Non-cached responses also get per-layer headers (X-Firewall-layer0-Ms etc.). latencyMs is then stripped from the response body before sending — body stays clean. HTTP status: block → 403, everything else → 200.
63–66 Export default + legacy DO stubs. export default app wires up the Worker. The additional export { KeyRevocation, RateLimiter } re-exports empty stub classes — required by Cloudflare while the deleted_classes Durable Object migration runs. These stubs return 410 Gone and will be removed once the migration completes.

Development

Workers AI bindings can't run locally — remote mode is required.

powershell
npm install

# Set auth token (PowerShell)
$env:CLOUDFLARE_API_TOKEN = "your-token"

# Run firewall-api (remote mode — uses real Cloudflare AI)
npm run dev:firewall   # → http://localhost:8787

# Run policy-manager (admin session cookie auth)
npm run dev:manager    # → http://localhost:8788

# Run firewall-tester (session cookie auth)
npm run dev:tester     # → http://localhost:8789

# Type-check everything
npm run typecheck
